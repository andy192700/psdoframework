# Version 1.3.0

Versioning upgrades:
- PowerShell 7.4 -> 7.6
- Dotnet 8 -> 10

Dependency injection (system wide, but user specific to composers and processes) now supports multiple constructors - favouring the largest.
- Composers still must only have the default constructor
- Processes (which are injected automatically) or classes found in modules which are injected as services via a Composer can have many constructors, the framework will favour the largest one it can satisfy
- Observability improved for the building of Processes, previously this could fail silently

Executing doing commands on a project (management or invocation) now benefit from hot reloads of ps1 files when invoked via a DoFile, meaning changes to Modules, Composers and Processes will be observed at run time, whereas previously this required reloading of a PowerShell terminal. This underlying issue is that once PowerShell classes are absorbed into the CLR via dot sourcing or module referencing they cannot be overwritten.

Removed superflous PowerShell version (PSVersion) from do.json files - we will never need this, the module version from which the project file was created survives as this may come into use later should the do.json structure change.
