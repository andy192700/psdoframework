# Version 1.3.2

Powershell class/dotnet interface mocking can be done outside of a doframework project, meaning a developer can use it anywhere provided they import/install this module. The sample dofile in the base of this repository has been outfitted with three examples demonstrating Powershell class mocking when classes are digested from the following:
- in line class defined before the mock is created
- dot sourced from a standalone ps1 file, referenced before the mock is created
- via module reference, at the top of the dofile, and the mock can be created as the class definitions from the module are brought into scope

Additional fixes:
- Hot reload (invocation via dofile, when `disableReload` is not supplied) had an issue with evaluating strings before invocation which stripped quotes breaking dotnet functional calls. This has been fixed by using an arguments list rather than an in line command call.
- Hot reload now imports the module as a first step, relevant if features of the framework are used in a target outside of a doing call (should this ever happen)
- Extra tests added to the E2E layer, ensuring our mock tests work for array/generic types rather than relying on the sample tests to prove this out
